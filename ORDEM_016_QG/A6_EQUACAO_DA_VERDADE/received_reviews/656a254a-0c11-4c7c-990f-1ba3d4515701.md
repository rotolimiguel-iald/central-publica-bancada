**Escopo exato do alvo.** Igualdade de **Leibniz** de objetos homogêneos:
1. `penalty ![Dc.toContinuousLinearMap, Db.toContinuousLinearMap, Dz.toContinuousLinearMap]` (que vive em `E →L[ℂ] E`) **coagido a `LinearMap`** = `TGL.FiniteThreeLocks.H3L Dc Db Dz` (que vive em `E →ₗ[ℂ] E`);

**Fixação de tipos.** `𝕜 = ℂ`, `E = EuclideanSpace ℂ (Fin n)`, `ι = Fin 3`, `Dc Db Dz : EuclideanSpace ℂ (Fin n) →ₗ[ℂ] EuclideanSpace ℂ (Fin n)`. A escolha de `EuclideanSpace ℂ (Fin n)` **não é ornamental**: `LinearMap.toContinuousLinearMap` e `LinearMap.adjoint` pedem dimensão finita (ou continuidade explícita); a versão geral exigiria `LinearMap.mkContinuous` + campo de continuidade, o que sairia do "mínimo".

## 2. P1 — adjunto comuta com a coerção (a única não-trivial)

Estado desejado (o nome sugerido pelo operador é a candidata):

```lean
/-- (P1) [CANDIDATO — a conferir] Forma exigida:
    (ContinuousLinearMap.adjoint (D.toContinuousLinearMap)).toLinearMap = LinearMap.adjoint D -/
theorem adjoint_clm_toLM_eq_lm_adjoint
    (D : EuclideanSpace ℂ (Fin n) →ₗ[ℂ] EuclideanSpace ℂ (Fin n)) :
    (ContinuousLinearMap.adjoint D.toContinuousLinearMap).toLinearMap
      = LinearMap.adjoint D :=
  LinearMap.adjoint_toContinuousLinearMap D   -- candidata; ver variações abaixo
```

**Variações a testar na bancada, nesta ordem:**
- se o lema estiver no sentido contrário, `exact (LinearMap.adjoint_toContinuousLinearMap D).symm`;
- se estiver enunciado como `⇑`, fechar com `LinearMap.ext`/`DFunLike.congr_fun`;
- **hipótese a conferir (não afirmação):** em muitas versões de mathlib `LinearMap.adjoint` *é definido* via `toContinuousLinearMap`; nesse caso P1 é `rfl` e a ponte inteira vira desdobramento puro.

**Fallback sem depender do nome** (caracterização por produto interno + unicidade do adjunto):

```lean
theorem adjoint_clm_toLM_eq_lm_adjoint'
    (D : EuclideanSpace ℂ (Fin n) →ₗ[ℂ] EuclideanSpace ℂ (Fin n)) :
    (ContinuousLinearMap.adjoint D.toContinuousLinearMap).toLinearMap
      = LinearMap.adjoint D := by
  apply LinearMap.ext; intro x
  apply eq_of_forall_inner_eq          -- helper abaixo; ‖·‖ de ⟨·,·⟩ fecha
  intro y
  rw [ContinuousLinearMap.adjoint_inner_left,
      LinearMap.adjoint_inner_left]     -- ambos caracterizam o mesmo adjunto
```

com o helper (usa só nomes já presentes no acervo: `inner_sub_left`, `inner_self_eq_norm_sq`, `norm_eq_zero`, `pow_eq_zero_iff two_ne_zero`):

```lean
theorem eq_of_forall_inner_eq
    (a b : EuclideanSpace ℂ (Fin n)) (h : ∀ x, inner ℂ a x = inner ℂ b x) : a = b := by
  have h2 : ∀ x, inner ℂ (a - b) x = 0 := fun x => by rw [inner_sub_left, h x, sub_self]
  have := h2 (a - b); rw [inner_self_eq_norm_sq] at this
  exact sub_eq_zero.mp (norm_eq_zero.mp (pow_eq_zero_iff two_ne_zero).1 this)
```

Forma pontual, para uso dentro de `ext`:

```lean
theorem adjoint_clm_apply_eq
    (D : EuclideanSpace ℂ (Fin n) →ₗ[ℂ] EuclideanSpace ℂ (Fin n))
    (x : EuclideanSpace ℂ (Fin n)) :
    ContinuousLinearMap.adjoint D.toContinuousLinearMap x = LinearMap.adjoint D x :=
  DFunLike.congr_fun (adjoint_clm_toLM_eq_lm_adjoint D) x
```
(se `⇑(·.toLinearMap)` não reduzir por `rfl`, interpolar `LinearMap.coe_toContinuousLinearMap`).

## 3. P2 — `penalty` = `H3L` como `LinearMap`

Primeiro a igualdade em `ContinuousLinearMap` (é o tipo que `reading` consome), depois a coação.

```lean
/-- (P2b) [CANDIDATO] Igualdade no nível `→L` — porta de entrada de `reading`. -/
theorem penalty_clm_eq_H3L_clm
    (Dc Db Dz : EuclideanSpace ℂ (Fin n) →ₗ[ℂ] EuclideanSpace ℂ (Fin n)) :
    penalty ![Dc.toContinuousLinearMap, Db.toContinuousLinearMap,
              Dz.toContinuousLinearMap]
      = (TGL.FiniteThreeLocks.H3L Dc Db Dz).toContinuousLinearMap := by
  have hsum :
      penalty ![Dc.toContinuousLinearMap, Db.toContinuousLinearMap,
                Dz.toContinuousLinearMap]
        = ContinuousLinearMap.adjoint Dc.toContinuousLinearMap * Dc.toContinuousLinearMap
            + ContinuousLinearMap.adjoint Db.toContinuousLinearMap * Db.toContinuousLinearMap
            + ContinuousLinearMap.adjoint Dz.toContinuousLinearMap * Dz.toContinuousLinearMap := by
    -- MESMO simp-set de TheEquationOfTruth.ker_threeLocks (linhas 82–85) [reuso]
    simp only [penalty, Fin.sum_univ_three, Matrix.cons_val_zero, Matrix.cons_val_one,
      Matrix.cons_val_two, Matrix.head_cons, Matrix.tail_cons]
  rw [hsum]
  ext x
  simp only [ContinuousLinearMap.add_apply, ContinuousLinearMap.mul_apply,
    TGL.FiniteThreeLocks.H3L, LinearMap.add_apply, LinearMap.comp_apply,
    LinearMap.coe_toContinuousLinearMap]
  simp only [adjoint_clm_apply_eq]        -- P1, três vezes
```

**Por que a associação fecha sem `ring`/`congr`:** `penalty ![a,b,c]` produz `(a + b) + c` (via `Fin.sum_univ_three`) e `H3L` é escrito `(adjoint Dc ∘ₗ Dc + adjoint Db ∘ₗ Db) + adjoint Dz ∘ₗ Dz` — **mesma associação à esquerda**. Sobram, em cada lado, exatamente três parcelas correspondentes. Preservação de tipos explícita: `*` (composição em `E →L[ℂ] E`) vira `∘ₗ`; `+` de `ContinuousLinearMap` vira `+` de `LinearMap`; `ContinuousLinearMap.adjoint` vira `LinearMap.adjoint` por P1; `⇑(D.toContinuousLinearMap) = ⇑D` por `LinearMap.coe_toContinuousLinearMap` (esperado `rfl`).

```lean
/-- (P2a) [CANDIDATO] O alvo do operador: igualdade de `LinearMap`. -/
theorem penalty_toLM_eq_H3L
    (Dc Db Dz : EuclideanSpace ℂ (Fin n) →ₗ[ℂ] EuclideanSpace ℂ (Fin n)) :
    (penalty ![Dc.toContinuousLinearMap, Db.toContinuousLinearMap,
               Dz.toContinuousLinearMap]).toLinearMap
      = TGL.FiniteThreeLocks.H3L Dc Db Dz := by
  rw [penalty_clm_eq_H3L_clm Dc Db Dz]
  exact LinearMap.coe_toContinuousLinearMap _
```

Sentido inverso (`P2a → P2b`), se a bancada preferir derivar tudo de um teorema só:
`ContinuousLinearMap.toLinearMap_injective (penalty_toLM_eq_H3L …)` — nome a conferir; fallback `ContinuousLinearMap.ext fun x => LinearMap.congr_fun (penalty_toLM_eq_H3L …) x`.

**Se a mathlib corrente não tiver `toLinearMap_add`/`toLinearMap_mul`** (rota curta por `simp` no nível `→L`), a rota acima — extensão em `x` com `ContinuousLinearMap.add_apply`/`mul_apply` — é a que não depende desses nomes.

## 4. P3 — `reading` = `PF`

`reading H` é `H.ker.starProjection` (evidência no próprio acervo: `TheEquationOfTruth` l.204 usa `Submodule.starProjection_eq_self_iff`) e `PF Dc Db Dz` é `(LinearMap.ker (H3L Dc Db Dz)).starProjection` (`FiniteThreeLocks` l.82–83). Logo a ponte é: **mesmo núcleo ⇒ mesmo projetor**.

```lean
/-- (P3) [CANDIDATO] `reading` coincide com `PF`. -/
theorem reading_eq_PF
    (Dc Db Dz : EuclideanSpace ℂ (Fin n) →ₗ[ℂ] EuclideanSpace ℂ (Fin n)) :
    reading (penalty ![Dc.toContinuousLinearMap, Db.toContinuousLinearMap,
                      Dz.toContinuousLinearMap])
      = TGL.FiniteThreeLocks.PF Dc Db Dz := by
  rw [penalty_clm_eq_H3L_clm Dc Db Dz]
  rfl   -- (a) ((H3L …).toCLM).ker = LinearMap.ker (H3L …) por defeq;
        -- (b) os dois lados são starProjection desse mesmo submódulo
```

**Riscos nomeados (a conferir, não defeitos presumidos):**
- `ContinuousLinearMap.ker` é `LinearMap.ker` do mapa coagido ⇒ a igualdade dos núcleos deve ser `rfl` (reforço: `LinearMap.coe_toContinuousLinearMap`).
- a instância `Submodule.HasOrthogonalProjection` precisa ser a mesma nos dois lados; em `EuclideanSpace ℂ (Fin n)` ela vem de dimensão finita/completude e deve unificar por defeq. Se `rfl` travar na instância: `congr 1` + `rfl` no submódulo; se ainda travar, usar a caracterização de unicidade da projeção ortogonal (`Submodule.isIdempotentElem_starProjection` + `PF_apply_mem` + ortogonalidade) em vez de igualdade direta de `starProjection`.

## 5. P4 (opcional, dentro da ponte) — `P = P† * P`

```lean
/-- (P4) [CANDIDATO] `PF = PF† * PF` — só isto; nada sobre runtime nem sobre K. -/
theorem PF_adjoint_eq
    (Dc Db Dz : EuclideanSpace ℂ (Fin n) →ₗ[ℂ] EuclideanSpace ℂ (Fin n)) :
    ContinuousLinearMap.adjoint (TGL.FiniteThreeLocks.PF Dc Db Dz)
      = TGL.FiniteThreeLocks.PF Dc Db Dz := by
  apply ContinuousLinearMap.ext; intro x
  apply eq_of_forall_inner_eq; intro y
  rw [ContinuousLinearMap.adjoint_inner_left, ← TGL.FiniteThreeLocks.PF_isSelfAdjoint]

theorem PF_eq_adjoint_mul_self
    (Dc Db Dz : EuclideanSpace ℂ (Fin n) →ₗ[ℂ] EuclideanSpace ℂ (Fin n)) :
    TGL.FiniteThreeLocks.PF Dc Db Dz
      = ContinuousLinearMap.adjoint (TGL.FiniteThreeLocks.PF Dc Db Dz)
          * TGL.FiniteThreeLocks.PF Dc Db Dz := by
  rw [PF_adjoint_eq]
  exact (TGL.FiniteThreeLocks.PF_isProjection Dc Db Dz).eq.symm
```
Generalização natural (se a bancada quiser): o mesmo corolário para `reading H` com `IsSelfAdjoint H` (no acervo, `isSelfAdjoint_penalty` dá a hipótese de graça), com `Submodule.isIdempotentElem_starProjection` no lugar de `PF_isProjection`.

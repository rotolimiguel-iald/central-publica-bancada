Rascunho de composição. **Não afirmo compilação, execução, prova nova, hash novo nem movimento de gate.** Apenas organizo o termo Lean candidato e o recorte de módulo necessário para evitar a duplicação de `NullSolution`.

## 1. Veredito curto

A composição mínima é:

```lean
fun h =>
  H3_of_null_solution h T G hG A hAu hAv hAt
    (hmc h) (hAn h) hc (hflat h)
    (construct_null_solution (W := W) T G A hc hi hm)
```

O ponto crítico: `produce` recebe `h : ContratoH2 W R N`. Portanto:

- `hmc`, `hAn` e `hflat` **precisam depender de `h`**;
- `hc`, `hi`, `hm` não dependem de `h`, pois falam só de `T` e `A`;
- `hAu`, `hAv`, `hAt` também não dependem de `h`;
- o índice `h2` de `ContratoImportH3 ... h2` **não** é usado dentro de `produce`; ele só tipa o resultado.

Se você usar `h2` dentro de `produce`, `same_horizon` vira `h2 = h`, que não fecha para todo `h`.

## 2. Duplicação de `NullSolution`

Há duas declarações textualmente coincidentes:

- `ProbeResidualH3v31.lean`: declara `TGLExt.ContratoQGv31.ProbeResidual.NullSolution` e `H3_of_null_solution`.
- `TeleologicalNullSolution_v2.lean`: redeclara `TGLExt.ContratoQGv31.ProbeResidual.NullSolution` e define `construct_null_solution`.

Coincidência textual de campos **não é** identidade de declaração. Se ambos os arquivos forem importados no mesmo ambiente, Lean acusa declaração duplicada. Também **não é** equivalência automática de tipos: se você renomear um deles, o outro não passa a ser o mesmo tipo; você precisaria de transporte explícito.

Portanto, a rota mínima é:

1. manter `ProbeResidualH3v31.lean` como dono canônico de `NullSolution` e `H3_of_null_solution`;
2. criar um módulo pequeno que **não importe** `TeleologicalNullSolution_v2.lean`;
3. nele, reusar o corpo de `construct_null_solution`, mas contra o `NullSolution` canônico.

## 4. Termo candidato para `ContratoImportH3`

Assumindo que `construct_null_solution` acima está no ambiente canônico:

```lean
open TGLExt.ContratoQGv31.ProbeResidual
open TGLExt.ContratoQGv31.ProbeResidual.Canonical

def contratoImportH3_of_null
    {W : TGLSpecificAQFTWitness} {R : TGLModularRealization W} {N : KillingNormalization}
    (T : StressTensorData W) (G : ℝ) (hG : 0 < G) (A : Set W.H)
    (hAu : ∀ ψ ∈ A, ‖ψ‖ = 1)
    (hAv : W.vac ∈ A)
    (hAt : ∀ (b : Fin 4 → ℝ) (ψ : W.H), ψ ∈ A → W.U b ψ ∈ A)
    (hc : ∀ ψ ∈ A, ∀ x : Fin 4 → ℝ,
      Continuous (fun l : ℝ => nullEnergy T ψ (x + l • nullDir)))
    (hi : ∀ ψ ∈ A, ∀ x : Fin 4 → ℝ, ∀ l : ℝ,
      IntegrableOn (fun u : ℝ => nullEnergy T ψ (x + u • nullDir)) (Ioi l))
    (hm : ∀ ψ ∈ A, ∀ x : Fin 4 → ℝ, ∀ l : ℝ,
      IntegrableOn (fun u : ℝ => u * nullEnergy T ψ (x + u • nullDir)) (Ioi l))
    (hmc : ∀ h : ContratoH2 W R N, ∀ ψ ∈ A, ∀ k : ℝ,
      HasModularEnergy h.Δit ψ k → k = 2 * Real.pi * nullPlaneCharge T ψ)
    (hAn : ∀ h : ContratoH2 W R N, ∃ ψ ∈ A, ∃ k : ℝ,
      HasModularEnergy h.Δit ψ k ∧ k ≠ 0)
    (hflat : ∀ h : ContratoH2 W R N, ∀ x ∈ rightWedge,
      screenBlock (solderMetric4 (h.E x)⁻¹) = -1)
    (h2 : ContratoH2 W R N) :
    ContratoImportH3 W R N T h2 where
  produce := fun h =>
    H3_of_null_solution h T G hG A hAu hAv hAt
      (hmc h) (hAn h) hc (hflat h)
      (construct_null_solution (W := W) T G A hc hi hm)
  same_horizon := by
    intro h
    rfl
```

Observações:

- `T`, `G`, `A` são preservados exatamente.
- `H3_of_null_solution` recebe o `h` corrente, não `h2`.
- `hmc h`, `hAn h`, `hflat h` são as hipóteses dependentes de `h`.
- `construct_null_solution` usa `hc`, `hi`, `hm`, que são as hipóteses de continuidade e integrabilidade de ordens zero e um nas caudas — o corpo já construído por A5.b.
- `same_horizon` fecha por `rfl` porque `H3_of_null_solution` define `H2 := C2`.

## 5. Controle negativo: `h2` fixo não fecha `same_horizon`

Esse controle mantém recusado o “import vazio”: ele mostra que não se pode pegar um `h2` fixo e usá-lo como se fosse todo `h`. O termo correto usa `h` recebido.

## 6. O que a composição não faz

Ela **não**:

- produz `ContratoH2` físico;
- constrói o tensor local `T0`;
- fecha o elo modular;
- deriva `hmc`, `hAn` ou `hflat`;
- transforma `construct_null_solution` em H3 sem `H3_of_null_solution`;
- identifica automaticamente as duas `NullSolution` textualmente iguais.

Ela apenas monta `ContratoImportH3` condicionalmente às hipóteses declaradas, reutilizando o `NullSolution` canônico e o corpo consumidor sem duplicar a declaração. Estatuto: **DECLARADO**, até revisão local da bancada.
